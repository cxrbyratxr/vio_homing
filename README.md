# VIO Homing

Рабочий ROS-пакет для Jetson Nano и Pixhawk 6C Mini: VINS-Fusion,
внешняя одометрия PX4, связь с QGroundControl через Wi-Fi и возврат по записанному пути.
**Система пока не объявляется готовой к полёту.** Реальное выполнение возврата и
посадки на собранном аппарате не подтверждено; причина периодического ожидания
IMU в VINS ещё не установлена.

## Окружение и подключения

- Jetson: Ubuntu 18.04 / JetPack 4.6, ROS Melodic, Python 2.7.
- Pixhawk: PX4 **1.16.0**, UART TELEM2; Jetson `/dev/ttyTHS1`, PX4 `/dev/ttyS3`,
  **460800 бод**, MAVLink 2. UART открывает только `mavlink_imu_bridge.py`.
- Камера USBGS1200P01: **640×480, YUYV, 30 Гц**, ROS `bgr8`.
- IMU: `HIGHRES_IMU`, запрашивается **200 Гц**; фактическая частота зависит от PX4
  и нагрузки. Справочное `IMU_INTEG_RATE=400` — другой параметр, не частота MAVLink.
- Jetson AP `VIO-HOMING`, адрес **192.168.50.1**; Mac подключается к этой сети.
- QGC на Mac принимает UDP **14550**, Jetson принимает команды UDP **14555**.
  IP Mac задаётся при запуске; источник GCS по умолчанию sysid=255 / compid=190.
- GPS не используется. Курс PX4 берёт из своей оценки с магнитометром;
  одна географическая точка не задаёт направление на север.

Камера и Pixhawk должны быть жёстко соединены с прежней взаимной ориентацией,
для которой получены extrinsics. Перестановка требует новой калибровки.

## Зависимости и сборка

Пакет находится на Jetson в `~/catkin_ws/src/vio_homing`.
В том же workspace должен быть установлен и собран пакет **`vins`** из
VINS-Fusion. Этот репозиторий не содержит исходники VINS, Ceres или PX4.

Нужны ROS `rospy`, `roslaunch`, `rosgraph`, `rosnode`, `sensor_msgs`, `geometry_msgs`,
`nav_msgs`, `std_msgs`, `cv_bridge`; Python 2.7 библиотеки NumPy, OpenCV с V4L2,
PyYAML и **совместимая с Python 2.7 версия pymavlink** с MAVLink 2 / ODOMETRY.
Не устанавливайте без проверки последний pymavlink в старое Python-окружение.
Пользователь `jetson` должен иметь доступ к UART и `/dev/video*`.

На остановленном стеке после обновления исходников:

```bash
source /opt/ros/melodic/setup.bash
cd ~/catkin_ws
catkin_make --pkg vio_homing -j1
source ~/catkin_ws/devel/setup.bash
mkdir -p ~/vio_data/vins/pose_graph
```

Это сборка данного пакета в существующем workspace, не установка VINS с нуля.
На Mac без ROS Melodic сборка и аппаратная проверка не выполняются.

## Точка старта на карте

До запуска задайте в **`config/map_origin.yaml`** координаты начала локальной
системы EKF. Текущие значения предоставлены владельцем:

```yaml
latitude_deg: 56.098828
longitude_deg: 35.869226
altitude_msl_m: 153.0
synthetic_reference: false
```

Высота — **метры над уровнем моря (MSL)**, не высота над землёй и не высота взлёта.
Для другой площадки измените конфиг до запуска, перезапустите разоружённый PX4
и начните новую сессию всех узлов. Другой уже наблюдавшийся origin не заменяется.

При запуске группы 01 узел `set_map_origin.py` передаёт
`SET_GPS_GLOBAL_ORIGIN` через общий мост, только при DISARM и landed.
Повторные запросы читают подтверждение и не сбрасывают маршрут повторно.
Ожидание подтверждения ограничено 120 с; отсутствие ответа выдаёт ошибку,
а не объявляет установку успешной. Отдельный шестой терминал не требуется.

Это привязка локального EKF к карте, **не FakeGPS/HIL_GPS**. QGC получает
`GLOBAL_POSITION_INT` от самого PX4. При неправильной точке карта будет
географически сдвинута. Для стрелки нужны также рабочая внешняя навигация и
глобальная позиция PX4; один origin не гарантирует их валидность и пригодность Mission.
Home принудительно не задаётся.

## Ручной запуск: два SSH-терминала

Подключитесь с Mac к Jetson в двух терминалах:

```bash
ssh jetson@192.168.50.1
```

**Перед первым запуском новой схемы остановите все старые пять групп**, включая
старый ROS master. Группа 01 сама поднимает master; отдельный `roscore` не нужен.
Скрипты подключают ROS-окружение, задают `ROS_IP=192.168.50.1`,
`ROS_MASTER_URI=http://localhost:11311` и удаляют старый `ROS_HOSTNAME`.

**Терминал 1 — master + PX4/IMU + TIMESYNC + QGC + контроль связи + траектория + homing:**

```bash
VIO_QGC_IP=192.168.50.213 ~/catkin_ws/src/vio_homing/scripts/manual/01_core.sh
```

Замените `192.168.50.213` на текущий Wi-Fi IP Mac. В QGC включите UDP link с
локальным портом 14550. Peer фиксирован: при смене IP Mac начните новую сессию
с правильным адресом на разоружённом стенде. Команды QGC пересылаются в PX4,
включая команды взлёта/миссии; сам Jetson не выдаёт ARM или Takeoff.
Дождитесь подключения PX4 и сообщения TIMESYNC OK / IMU READY.

**Терминал 2 — камера + VINS + адаптер:**

```bash
~/catkin_ws/src/vio_homing/scripts/manual/02_vio.sh
```

Группа 02 требует работающую группу 01 и не создаёт отдельный master.
Инициализация VINS, сообщения камеры и адаптера видны во втором терминале.
Плавно переместите и наклоните жёстко соединённые камеру с Pixhawk перед
освещённой текстурной сценой, затем оставьте неподвижно. После инициализации
адаптер ждёт **3 с стабильных данных**, затем сообщает `ACTIVE`.

Это две группы запуска, внутри которых сохранены отдельные ROS-узлы и топики.
Скрипты работают на переднем плане. При выходе критического узла останавливается
его группа. Узел установки origin одноразовый и не считается критическим.
**Нет systemd, respawn или автоматического переподключения MAVLink.** Старые
сервисы `vio-homing` / `vio-wireless` должны оставаться отключёнными.
AP и SSH — отдельные сетевые службы, этот пакет их не останавливает.

Остановка разоружённого стенда: Ctrl+C во втором терминале, затем в первом.
После перезагрузки Pixhawk, срыва VINS или FAULT остановите **обе** группы,
восстановите оборудование, запустите 01→02 и повторите инициализацию.
Перезапуск только VINS/группы 02 со старой сессией возврата не допускается.

### Варианты запуска

Без команд автоматического возврата, но с одометрией и QGC relay:

```bash
VIO_QGC_IP=192.168.50.213 ~/catkin_ws/src/vio_homing/scripts/manual/01_core.sh enable_homing_commands:=false
```

Это запрещает **автоматические homing-команды**, но не команды оператора QGC.
Другой конфиг точки старта: `map_origin_config:=/home/jetson/my_origin.yaml`.
Отключить установку origin: `configure_map_origin:=false`.
Параметры core задаются аргументами `core.launch`; камеры и VINS — `vio.launch`.
Например, временно выбрать `/dev/video0`:

```bash
~/catkin_ws/src/vio_homing/scripts/manual/02_vio.sh camera_device:=/dev/video0
```

Опрос PX4 health использует общий NSH-канал. **Не открывайте QGC MAVLink Console
одновременно с опросом.** Для консоли на разоружённом стенде запускайте 01 с
`enable_px4_health_probe:=false enable_homing_commands:=false`.
Без health probe автоматический возврат заблокирован. MAVLink Inspector QGC
не использует NSH и доступен при обычном запуске.

## Наблюдение в дополнительном терминале

```bash
source ~/catkin_ws/devel/setup.bash
unset ROS_HOSTNAME
export ROS_IP=192.168.50.1 ROS_MASTER_URI=http://localhost:11311
rosrun vio_homing vins_displacement.py
```

`r` + Enter задаёт новый ноль **индикатора**, не сбрасывает VINS, EKF2 или FAULT.
Индикатор показывает raw VINS; PX4 принимает только данные, прошедшие адаптер.
Основные состояния:

```bash
rostopic echo /vio_homing/link_state
rostopic echo -n 1 /vio_homing/imu_status
rostopic echo -n 1 /vio_homing/vins_adapter_status
rostopic echo -n 1 /vio_homing/mavlink_transport_status
rostopic echo /vio_homing/homing_state
rostopic echo /vio_homing/homing_reason
```

`ground_navigation_ready` означает локальную готовность входов и согласования;
`return_ready` дополнительно требует пригодного курса PX4. Ни один флаг не
является разрешением взлёта. `waiting for IMU...` при запуске VINS возможно;
периодические ожидания после инициализации требуют выяснения разрывов потока,
задержек и временных меток. Средние 200 Гц сами по себе не исключают провалы.

## Архитектура и интерфейсы

```text
камера + IMU Pixhawk → VINS → адаптер → /vio/odom_frd → ODOMETRY → EKF2
                                         ├→ trajectory_recorder
QGC heartbeat → wifi_link_monitor ────────┴→ homing_manager
                                               ↓ текущая цель
                               MAVLink-мост → OFFBOARD setpoint → PX4
```

| Данные | ROS topic | Тип |
|---|---|---|
| Камера | `/camera/image_raw` | `sensor_msgs/Image` |
| IMU | `/pixhawk/imu` | `sensor_msgs/Imu` |
| Raw VINS | `/vins_estimator/odometry` | `nav_msgs/Odometry` |
| Внешняя одометрия | `/vio/odom_frd` | `nav_msgs/Odometry` |
| Поза EKF PX4 | `/vio_homing/px4_odometry` | `nav_msgs/Odometry` |
| Связь | `/vio_homing/link_state` | `std_msgs/String` |
| Записанный / обратный путь | `/vio_homing/trajectory`, `/vio_homing/return_path` | `nav_msgs/Path` |
| Последняя точка с хорошей связью | `/vio_homing/last_good_link_pose` | `geometry_msgs/PoseStamped` |
| Текущая цель | `/vio_homing/return_goal` | `geometry_msgs/PoseStamped` |
| Состояние / причина | `/vio_homing/homing_state`, `/vio_homing/homing_reason` | `std_msgs/String` |
| Активность / намерение LAND | `/vio_homing/return_active`, `/vio_homing/land_command` | `std_msgs/Bool` |
| Диагностика моста / ACK | `/vio_homing/mavlink_transport_status`, `/vio_homing/mavlink_command_ack` | `std_msgs/String` (JSON) |

`ODOMETRY` передаёт **оценку положения**. `SET_POSITION_TARGET_LOCAL_NED`
передаёт **цель управления**: frame LOCAL_NED, XYZ, маска 3576, около 20 Гц.
Режим меняется через `COMMAND_LONG / MAV_CMD_DO_SET_MODE` (176),
посадка — `COMMAND_LONG / MAV_CMD_NAV_LAND` (21). Весь return_path хранится
на Jetson, в PX4 как Mission не загружается. ACK и фактический режим учитываются отдельно.

## Логика записи и возврата

- Recorder принимает свежую `/vio/odom_frd`; новая точка при расстоянии ≥0.25 м
  либо интервале ≥1 с. Буфер до 20000 точек, хранится в памяти текущей сессии.
- Пока heartbeat QGC свежий, фиксируется последняя хорошая точка.
  При отсутствии heartbeat ≥2 с — `LINK_DEGRADED`, ≥4 с — `LINK_LOST`.
  Пропадание картинки или SSH само по себе не является критерием потери связи.
- После подтверждённой потери обратный сегмент замораживается от текущего
  записанного положения к `last_good_link_pose`, не обязательно к месту взлёта.
- `RETURN`: текущая цель меняется после расстояния ≤0.4 м и скорости ≤0.5 м/с
  непрерывно ≥0.5 с. Требуется свежая одометрия.
- В воздухе мост проверяет armed/in-air, навигацию, профиль PX4, время и
  согласование, передаёт поток удержания ≥1.2 с и запрашивает OFFBOARD.
  Вход подтверждается фактическим режимом, тайм-аут 3 с.
- На конечной точке `WAIT_LINK` удерживает её в OFFBOARD **не менее 60 с**.
  Выход из области/рост скорости сбрасывает таймер ожидания.
- Связь вернулась в RETURN/WAIT_LINK — отмена возврата и передача в **Hold**;
  Mission автоматически не продолжается. Уже начатая LAND автоматически не отменяется.
- Нет улучшения дистанции ≥0.15 м за 15 с, цель не достигнута за 60 с,
  пустой путь >3 с, потеря одометрии или невозможность удержать конец 15 с — `ABORT`.
  LAND/ABORT формируют намерение посадки; мост проверяет актуальность и состояние PX4.
- Команды flight-контроллера запрещены при DISARM или отсутствии признака полёта.
  Отказы OFFBOARD/навигации приводят к ограниченному запросу LAND; бесконечного
  повтора нет. При потере UART действуют штатные failsafe PX4.
- Смена режима оператором после захвата прекращает управление Jetson.

Обычный Mission выполняется самим PX4 после команды оператора QGC; взлёт можно
включить в миссию либо выполнить отдельно с последующим запуском миссии.
Mission требует загруженного плана и пригодной глобальной навигации.

## Координаты, время и EKF2

Raw VINS: gravity-aligned world с произвольным yaw, тело IMU FLU.
Преобразование с `C=diag(1,-1,-1)`:

```text
p_local_frd = C · p_world
R_local_frd_body_frd = C · R_world_imu_flu · C
v_body_frd = C · R_world_imu_fluᵀ · v_world
p_px4_ned = Rz(yaw_alignment) · p_local_frd + origin_alignment
```

Первая замена осей не устанавливает географический север. Согласование с PX4
оценивается по парам поз с разницей времени ≤0.12 с, стабильным ≥1 с,
и затем контролируется. Сброс EKF при возврате блокирует согласование.
Завершение магнитного выравнивания до возврата может потребовать новой регистрации.
В PX4 1.16 `heading_good_for_control=False` на земле при магнитометре само по себе
не означает отказ; для захвата возврата требуется True.

IMU переводится из FRD в FLU и публикуется только после TIMESYNC. Сброс/обратный
ход sensor time либо разрыв >0.5 с блокирует сессию. Часы Jetson должны быть
актуальны до запуска; не меняйте их во время работы навигации.

VINS `td` и аргумент `adapter_stamp_offset` группы 02 согласованы: **−0.03275171186939631 с**.
VINS интегрирует до image timestamp + td; адаптер этим же смещением маркирует
время выходного состояния. Не добавляйте ещё такую поправку в драйвер камеры.

Справочный профиль `config/px4_vio_homing.params`: `EKF2_EV_CTRL=7`
(внешние XY, высота, скорость, **без yaw VINS**), `EKF2_HGT_REF=0` и
`EKF2_BARO_CTRL=1` — барометрическая опора высоты. Это слияние, не подмена GPS.
Профиль при запуске только читается. Параметры автоматически не импортируются.
Для штатных порогов требуется `COM_DL_LOSS_T≥9.2 с` (справочное значение 10 с),
`COM_OF_LOSS_T=1`, `COM_OBL_RC_ACT=4`, `COM_DLL_EXCEPT` с битом 4,
`COM_RCL_EXCEPT` с битами 2 и 4, `NAV_DLL_ACT=3`; остальные значения — в файле.
Изменение failsafe требует отдельного осмысленного применения под конкретный аппарат.

## Калибровка и ограничения

Активный VINS-конфиг: `config/vins/usbgs1200p01_mono_imu.yaml`;
intrinsics: `config/vins/usbgs1200p01_pinhole.yaml`.
`body_T_cam0` — обратная Kalibr `T_cam_imu`, camera optical → IMU FLU.
Калибровка предварительная: достигался лимит оптимизации, есть большие
остаточные ошибки; IMU noise в VINS пока взят из примера, а не измерен.
Не менять разрешение, фокус, крепление, обработку timestamp без пересмотра калибровки.
Принудительный `CAP_PROP_BUFFERSIZE=1` не используется: на этом стенде он снижал FPS.
VINS читает intrinsics из собственного конфига; отсутствие `/camera/camera_info`
при пустом `camera_info_file` не мешает текущему VINS.

Адаптер проверяет frame, quaternion, свежесть, непрерывность времени,
скорость ≤5 м/с, изменение скорости ≤12 м/с², шаг ≤1 м и ≤5·dt+0.15 м,
угловую скорость ≤5 рад/с. Срыв после ACTIVE фиксирует FAULT и прекращает одометрию.
Это не исключает медленный дрейф или согласованно неправильные оценки VINS/EKF.

Read-only health probe через SERIAL_CONTROL/NSH остаётся ограничением реализации:
нужен свободный канал консоли, ответ не старше 4 с; специального выделенного
потока health из PX4 пока нет. Поведение полного аппарата и всех failsafe
совместно ещё предстоит подтвердить. Стрелка QGC, успешный ARM check или
публикация одометрии не означают готовность системы к полёту.

## Состав репозитория

- `scripts/manual/` — `01_core.sh`, `02_vio.sh` и общее окружение.
- `scripts/` — рабочие ROS-узлы, установка map origin, индикатор VINS.
- `src/vio_homing/` — возврат, MAVLink transport, координаты и контроль данных.
- `launch/core.launch` — PX4, связь и homing; `launch/vio.launch` — камера, VINS и адаптер.
- `config/` — калибровка, VINS, origin и справочные параметры PX4.
- `CMakeLists.txt`, `package.xml`, `setup.py` — catkin-пакет.

Стендовые сценарии, проверочные скрипты, старые установщики, дублирующие launch
и исторические документы удалены из текущего дерева. Предыдущие версии
доступны в истории Git. Единственная инструкция — этот README.
