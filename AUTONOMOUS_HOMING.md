# VINS, EKF2 и управление возвратом

Состояние интеграции: 21.10.2026, Jetson Nano / PX4 Release 1.16.0
(6ea3539157ca358c70a515878b77077af7d4611d). Реальное выполнение возврата и
посадки вооружённым аппаратом пока не проверено. Дрейф VINS принят как допущение
для этого этапа, точность и требования ТЗ этим не подтверждены.

## Запуск

`vio-wireless.service` запускает `run_wireless.sh` → `wireless.launch`:
камера, IMU/MAVLink/QGC, VINS, адаптер, recorder, manager, браузерное видео.
Не запускайте второй экземпляр этих узлов вручную.

```bash
sudo systemctl restart vio-wireless.service
source ~/catkin_ws/devel/setup.bash
unset ROS_HOSTNAME
export ROS_IP=192.168.50.1 ROS_MASTER_URI=http://localhost:11311
rostopic echo /vio_homing/mavlink_transport_status
rostopic echo /vio_homing/vins_adapter_status
```

Для инициализации VINS нужно движение жёсткой сборки камера–IMU перед текстурной
сценой. После VINS FAULT перезапускается весь стек на земле: старый маршрут и
система координат не должны переживать сброс оценивателя. Автоматическое
восстановление ошибочной VIO в полёте не реализовано.

## Интерфейсы и координаты

| Назначение | ROS | Тип / MAVLink |
|---|---|---|
| Исходная VINS | `/vins_estimator/odometry` | nav_msgs/Odometry, world/world |
| Внешняя одометрия | `/vio/odom_frd` | nav_msgs/Odometry, local_frd/body_frd → ODOMETRY(331) |
| Обратный путь | `/vio_homing/return_path` | nav_msgs/Path, local_frd |
| Текущая цель | `/vio_homing/return_goal` | geometry_msgs/PoseStamped, local_frd |
| Состояние / LAND | `/vio_homing/homing_state`, `/vio_homing/land_command` | std_msgs/String / Bool |
| Поза оценивателя PX4 | `/vio_homing/px4_odometry` | nav_msgs/Odometry, px4_local_ned/body_frd; только pose, twist не используется |
| Диагностика | `/vio_homing/mavlink_transport_status` | std_msgs/String, JSON |
| Передачи / ACK | `/vio_homing/mavlink_tx_event`, `/vio_homing/mavlink_command_ack` | std_msgs/String, JSON |

VINS world имеет вертикаль вверх и произвольный yaw. Для C=diag(1,-1,-1):
p_F=C p_V; R_F=C R_V C; v_body_FRD=C R_V^T v_world. Метка состояния
равна VINS header + td; это учёт фактического времени оптимизированного состояния.
Данные отправляются как MAV_FRAME_LOCAL_FRD / MAV_FRAME_BODY_FRD, не под видом NED.
См. VINS_SETUP.md для калибровки и ограничений.

Для целей отдельно оценивается фиксированный поворот yaw и перенос:
p_NED = Rz(yaw) p_F + origin. Используются синхронные позы VINS и возвращаемая
PX4 ODOMETRY с MAV_FRAME_LOCAL_NED и estimator_type=AUTOPILOT. Не менее 10 пар
за ≥1 с, рассогласование времени ≤0.12 с, согласованные вертикали ≤10°,
стабильность yaw ≤3° и переноса ≤0.2 м. Согласование разрешено только disarmed
при валидной позиции EKF; затем фиксируется. Сброс EKF, VINS FAULT или разрыв
MAVLink блокирует прежнее согласование. Это согласование локальных координат,
а не независимое доказательство географического курса или точности.

## Управление

`companion.launch` по умолчанию сохраняет старый режим bench с командами выключенными.
`wireless.launch` выбирает flight, автоматическое согласование и команды включены.
Flight контроллер никогда не отправляет ARM и не подменяет landed_state.
На disarmed/наземном стенде OFFBOARD и LAND этим контроллером не запрашиваются.

Перед захватом управления обязательны: свежие VIO/EKF, TIMESYNC, согласование,
подтверждённый профиль параметров PX4, свежий homing_session/state, armed и
фактический EXTENDED_SYS_STATE.IN_AIR. Отсутствие условия блокирует захват.

При RETURN: удержание текущей позиции с потоком 20 Гц в течение ≥1.2 с,
затем COMMAND_LONG / MAV_CMD_DO_SET_MODE(176), main=6 OFFBOARD. Принятого ACK
недостаточно: требуется OFFBOARD в heartbeat. После этого текущая цель manager
передаётся в SET_POSITION_TARGET_LOCAL_NED(84), frame=LOCAL_NED, mask=3576
(только XYZ; скорость, ускорение и yaw игнорируются). Весь путь остаётся на Jetson.

WAIT_LINK удерживает последнюю цель; manager выдерживает ≥60 с. LAND передаётся
однократно COMMAND_LONG / MAV_CMD_NAV_LAND(21), затем ожидается режим AUTO.LAND
(main=4, sub=6). ACK и режим диагностируются отдельно. Повторная LAND при каждом
тике и автоматический повтор после неизвестного результата запрещены.

Восстановление связи при RETURN/WAIT_LINK: manager возвращается в NORMAL,
контроллер запрашивает AUTO.LOITER/Hold (4,3), удерживая текущую позицию до
подтверждения выхода из OFFBOARD, затем прекращает поток. Старый LAND отменён.
Возврат оператора к управлению после Hold выполняется через QGC. Смена режима
оператором/PX4 после захвата прекращает вмешательство контроллера.

Отказ OFFBOARD или потеря навигации/входных данных после захвата → однократный
LAND. Если LAND не подтверждён за 5 с, поток прекращается и остаётся failsafe PX4.
При потере UART поток также прекращается. Перезапуск manager во время владения
OFFBOARD → LAND; перезапуск всего процесса теряет поток → failsafe PX4.

## Профиль PX4

Профиль применён после явного согласия владельца, контроллер перезагружен,
значения прочитаны повторно. `config/px4_vio_homing.params` — справочный файл,
не автоматический импорт. Резервная копия на Jetson:
`~/vio_backups/control_stage/params_before_decoded.json`.

- EKF2_EN=1, EKF2_EV_CTRL=7: внешняя XY/Z позиция и скорость; EV yaw выключен.
- EKF2_HGT_REF=3; EKF2_EV_NOISE_MD=1, EVP/EVV_NOISE=0.2 (начальные настройки,
  не измеренная ковариация VINS). EV_DELAY=0: td уже учтён. EV_POS_X/Y/Z=0:
  публикуется поза IMU, повторный рычаг камеры не нужен.
- COM_DLL_EXCEPT=4: GCS loss игнорируется в OFFBOARD, чтобы Jetson завершал возврат.
- COM_RCL_EXCEPT=6: отсутствие RC допускается в Hold/OFFBOARD.
- NAV_DLL_ACT=3: GCS loss вне исключений → LAND.
- COM_OBL_RC_ACT=4, COM_OF_LOSS_T=1: потеря OFFBOARD-потока → LAND через 1 с.
- COM_DL_LOSS_T=10, COM_FAIL_ACT_T=5 оставлены прежними. Прочие failsafe,
  arming checks, GPS/baro/mag настройки и safety не отключались.

Bridge только читает и проверяет профиль перед управлением; параметры сам не
переписывает. Эти исключения меняют поведение при потере GCS/RC и требуют
сохранения согласованной логики Jetson и PX4.

## Границы подтверждения

Сборка пакета и 41 Python2 unit-тест прошли. Реальные параметры PX4 сохранены
после перезагрузки; стек запускает 9 узлов, IMU около 200 Гц, камера около 30 Гц.
Логи: verification/control_stage/. Итоговый runtime.json содержит фактические
флаги, счётчики и результат согласования; не считать включение EV параметров
доказательством fusion без соответствующих данных оценивателя.

Наземное следование OFFBOARD и LAND этим flight контроллером не проверяются
через подмену IN_AIR/ARM. Алгоритм переходов и преобразование координат проверены
отдельно; выполнение управления на полноценном БВС остаётся следующим этапом.
Требование ТЗ VO≥20 Гц отдельно не подтверждено. Предварительная калибровка,
GPS-триггер, полётная точность, аппаратные датчики и силовая часть остаются
отдельными задачами. Система не объявляется готовой к полёту.

### Результат живого включения

В последней сессии VINS и адаптер начали выдачу; мост отправил 168 ODOMETRY
без ошибок, PX4 передавал собственную ODOMETRY и ESTIMATOR_STATUS. Затем VINS
выдал скачок >1 м за соседние позы (журнал показывал координаты порядка десятков
метров), адаптер перешёл в `FAULT: Position discontinuity`. Согласование осталось
невалидным, управляющие setpoint/LAND не отправлялись. Устойчивое использование
EV оценивателем и рабочее согласование в этой сессии НЕ подтверждены.
Нельзя считать принятое допущение об отсутствии дрейфа результатом измерения.
Перед продолжением нужна диагностика VINS/калибровки/времени и новая наземная сессия.
Стартовый старый кадр теперь отбрасывается до первой свежей позы; после запуска
проверки свежести и скачков сохраняются с фиксацией FAULT.
