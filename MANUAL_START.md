# Ручной запуск на Jetson

На текущем Jetson прежние сервисы vio-wireless/vio-homing отключены и замаскированы.
Шаблоны и установщик этих сервисов удалены из репозитория.
Wi-Fi AP и SSH остаются работать; их сетевые службы не отключаем.
Нет автоматического respawn узлов и повторного подключения MAVLink по умолчанию.
Браузерное видео и панель не запускаются.

Открыть пять SSH-терминалов. В каждом выполнить соответствующую команду:

```bash
# 1. ROS master
~/catkin_ws/src/vio_homing/scripts/manual/01_master.sh

# 2. PX4, IMU, TIMESYNC и QGC relay (указать текущий Wi-Fi IP Mac)
VIO_QGC_IP=192.168.50.213 ~/catkin_ws/src/vio_homing/scripts/manual/02_px4.sh

# 3. Монитор связи, запись траектории, homing_manager
~/catkin_ws/src/vio_homing/scripts/manual/03_logic.sh

# 4. Камера: 640x480, YUYV, цвет, 30 Гц
~/catkin_ws/src/vio_homing/scripts/manual/04_camera.sh

# 5. VINS и адаптер, вывод инициализации здесь
~/catkin_ws/src/vio_homing/scripts/manual/05_vins.sh
```

Это команды для разных терминалов, не один последовательный блок.
После готовности потоков камеры и IMU плавно переместить и наклонить жёстко
соединённые камеру и Pixhawk для инициализации VINS.

Скрипты работают на переднем плане. Ctrl+C останавливает соответствующую группу.
Второй экземпляр группы блокируется проверкой ROS-регистрации.
При аварии отдельный узел не возрождается; проверить вывод и запустить вручную.
02_px4 сохраняет прежнее включение homing-команд; для одних наблюдений можно
передать `enable_homing_commands:=false`. ARM скрипты не выполняют.

Полная остановка: Ctrl+C в терминалах 5, 4, 3, 2 и последним 1.
Перезагрузка Pixhawk, FAULT адаптера или сброс VINS требуют новой сессии:
на разоружённом стенде остановить все пять групп, дождаться Pixhawk,
запустить заново 1→5 и повторить инициализацию. Маршрут и согласование сбрасываются.
Не перезапускать только VINS со старым маршрутом.

Для прежнего индикатора перемещения можно отдельно выполнить:

```bash
source ~/catkin_ws/devel/setup.bash
rosrun vio_homing vins_displacement.py
```

Старые общие launch, systemd unit и установщик автозапуска удалены.
Для текущего режима использовать только scripts/manual.

## Условный global origin для стенда без GPS

После полного ручного запуска обновлённого стека на разоружённом стенде:

```bash
source ~/catkin_ws/devel/setup.bash
rosrun vio_homing set_bench_origin.py
```

Однократный SET_GPS_GLOBAL_ORIGIN через существующий мост; отдельный доступ к UART не открывается.
Пример: 55.810249 / 37.500816, 168 м MSL. Координаты — ориентир около адреса
МАИ 4к3 из муниципального реестра, не геодезическая точка борта; 168 м — рельеф
Open-Meteo elevation, не этаж/высота IMU. Данные условные, только для стенда.
Источники:
https://www.mos.ru/upload/documents/files/1430/5_Prilojenie5.pdf
https://api.open-meteo.com/v1/elevation?latitude=55.810249&longitude=37.500816

Только совпавший обратный GPS_GLOBAL_ORIGIN означает подтверждение приёма.
Нет ответа — результат не подтверждён. Другой уже наблюдавшийся origin не заменяется.
Скрипт не задаёт Home, не загружает миссию, не переключает режим, не ARM и не
публикует GPS/HIL_GPS. Задание origin не исправляет yaw/VINS и не гарантирует
валидность глобальной оценки. В QGC проверить vehicle_local_position
(ref_lat/ref_lon/ref_alt, xy_global/z_global, heading_good_for_control),
vehicle_global_position и commander check. Прежние маршруты до изменения
привязки не использовать: начинать новую ручную сессию.

## Шестой терминал

После запуска 01→05 и инициализации VINS:

```bash
source ~/catkin_ws/devel/setup.bash
unset ROS_HOSTNAME
export ROS_IP=192.168.50.1 ROS_MASTER_URI=http://localhost:11311
rosrun vio_homing set_bench_origin.py
```

Origin задаётся один раз на сессию PX4. После принятия координат не посылать
повторно только из-за тайм-аута скрипта: сначала проверить ref_lat/ref_lon/ref_alt
и xy_global/z_global через listener vehicle_local_position. Тайм-аут
подтверждения ранее наблюдался при фактически принятом origin.
При выключении всего стенда сначала остановить ROS-группы; при новом
запуске повторить последовательность. Перезапуск PX4 с живым VINS недопустим.

## Доработки контроля

После обновления полностью перезапустить пять ручных групп. После инициализации
VINS адаптер ожидает 3 с стабильных данных; резкий срыв блокирует одометрию.
Параметры, ABORT и диагностические return_ready/ground_navigation_ready описаны
в SAFETY_BEHAVIOR.md. Отдельная панель и автозапуск не возвращались.
Прямой опрос PX4 health использует общий NSH-канал: QGC MAVLink Console
одновременно не открывать. Обычная телеметрия QGC продолжает работать.
