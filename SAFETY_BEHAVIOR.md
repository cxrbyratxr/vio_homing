# Поведение при отказах — 23.10.2026

Это программные ограничения стенда, а не подтверждение полётной готовности.
ARM, взлёт и изменение параметров PX4 код не выполняет.

## VINS → адаптер

После инициализации ожидаются 3 секунды подряд правдоподобных поз. До этого
адаптер сообщает WAITING_FOR_STABLE_VINS и не публикует /vio/odom_frd.
Проверяются конечные значения, единичный quaternion, frame, возраст/порядок
времени, разрыв IMU, скорость ≤5 м/с, изменение скорости ≤12 м/с²,
межкадровый шаг ≤1 м и ≤5*dt+0.15 м, угловая скорость ≤5 рад/с.
Пороговые значения предварительные для текущего стенда, задаются ROS-параметрами.
После ACTIVE нарушение блокирует сессию (FAULT); плохая поза не передаётся PX4.
На старте нарушение перезапускает интервал стабилизации, не разрешая передачу.
Непрерывность IMU и TIMESYNC проверяются отдельно в мосте.

Это распознаёт резкое расхождение; медленный дрейф, ошибку масштаба и
согласованно неверные VINS/EKF этими проверками исключить нельзя.

## Маршрут и достижение

- Цель: расстояние ≤0.4 м и оценка скорости ≤0.5 м/с непрерывно ≥0.5 с.
- Новая цель сбрасывает проверку продвижения.
- Нет улучшения дистанции минимум на 0.15 м за 15 с либо цель не достигнута
  за 60 с → ABORT / RETURN_NO_PROGRESS.
- Нет пригодного пути через 3 с после LINK_LOST → ABORT / NO_USABLE_RETURN_PATH.
- Потеря свежей одометрии → ABORT / ODOMETRY_LOST.
- WAIT_LINK считает ≥60 с только при свежей позе внутри конечной области
  и малой скорости. Выход сбрасывает таймер; невозможность удержать область
  15 с → ABORT / ENDPOINT_NOT_HELD.
- Возвращение LINK_OK отменяет RETURN/WAIT_LINK/ABORT и старые таймеры.

ABORT публикуется как отдельное состояние и LAND intent. Мост на разоружённом
или наземном стенде не выполняет flight-команды. В воздухе при свежем запросе
от manager выполняется однократный запрос NAV_LAND. Отказ/тайм-аут ACK/режима
фиксируется, бесконечных повторов нет. Выполнение посадки остаётся за PX4;
потеря пригодной высоты может помешать выполнению LAND.

## PX4 health и согласование

PX4 1.16 выставляет старый MAVLink бит CONST_POS_MODE также при vehicle_at_rest.
Поэтому этот бит сам по себе больше не блокирует согласование на земле.
Проверяются attitude, локальная позиция/скорости, активное горизонтальное
содействие и отсутствие флага ошибки акселерометра.

heading_good_for_control читается непосредственно из vehicle_local_position.
В PX4 1.16 при использовании компаса финальное выставление курса завершается
в воздухе; False на земле не трактуется как поломка компаса. ground_navigation_ready
проверяет локальную навигацию, согласование и профиль непрерывно 3 с, но не ARM.
return_ready дополнительно требует heading_good_for_control=True.
Оба признака диагностические; они не являются разрешением взлёта.

Стандартный ESTIMATOR_STATUS не содержит прямой heading_good_for_control.
Текущая реализация опрашивает фиксированную read-only NSH-команду
`listener vehicle_local_position 1` через SERIAL_CONTROL на уже открытом MAVLink.
Нет пользовательских команд, отдельного UART reader или новых сервисов ОС.
Ответ ограничен 16 КБ, тайм-аутом 2 с; порт освобождается после ответа/тайм-аута.
Интервал запросов 1.5 с, максимум возраста результата 4 с, время самого
измерения проверяется через TIMESYNC. Нет ответа — захват RETURN запрещён.
Если RETURN не может захватить управление 3 с из-за неготовых входов,
запрашивается LAND при соблюдении armed/in-air gates.

Это диагностический мост для текущей прошивки, не специальный поток uORB.
Одновременно пользоваться QGC MAVLink Console нельзя: у NSH общий канал;
конфликт делает health непригодным и может вызвать аварийный выход из возврата.
Для дальнейшей полётной версии предпочтителен выделенный поток состояния
из прошивки PX4. При отключении ~enable_px4_health_probe захват RETURN блокируется,
а не разрешается по догадке.

Смена origin, готовность новой VINS-сессии и сброс PX4 на земле создают
navigation_epoch. Recorder очищает маршрут, manager создаёт новый session UUID,
мост заново согласует frame. Цели старой сессии не переиспользуются.
Если PX4 завершает выставление магнитного курса в воздухе до возврата,
допускается новая регистрация frame по свежим, согласованным парам VIO/PX4
за ≥1 с, только в NORMAL и без владения управлением. VIO-маршрут при этом
остаётся в прежнем VIO frame. Во время RETURN/WAIT_LINK сброс EKF2 не допускает
такой подстройки: согласование блокируется, контроллер запрашивает LAND.
После регистрации рассогласование VIO/PX4 >1 м или вертикалей >15°,
сохраняющееся ≥0.5 с, блокирует согласование.

## PX4 failsafe

Профиль только читается; настройки не изменяются. Дополнительно читаются
COM_DL_LOSS_T и COM_FAIL_ACT_T. Для default LINK_LOST=4 с требуется
COM_DL_LOSS_T ≥4+1.2+3+1=9.2 с: детекция + prestream + ожидание OFFBOARD + запас.
Фактический lost_timeout берётся из wifi_link_monitor. При несовместимом бюджете
захват OFFBOARD запрещён. Это проверка бюджета, а не доказательство поведения
комбинации всех failsafe PX4. Остальные значения профиля сохраняются.

Потеря UART/процесса прекращает proof-of-life OFFBOARD; действуют штатные failsafe
PX4. Переключение режима оператором после захвата прекращает выдачу целей.
Отказ OFFBOARD и потеря навигации во время возврата дают однократный запрос LAND.
Критическое состояние PX4 не переопределяется. Отказы связи и отсутствие валидной
навигации не обходятся отключением защит.

## Автономные регрессии

На Jetson с ROS Melodic/Python 2.7, без открытия UART и без ROS master:

```bash
source ~/catkin_ws/devel/setup.bash
cd ~/catkin_ws/src/vio_homing
PYTHONPATH="$PWD/src:$PYTHONPATH" python tools/check_homing_safety.py
PYTHONPATH="$PWD/src:$PYTHONPATH" python tools/check_ros_safety.py
```

Второй сценарий подменяет только ROS I/O и MAVLink transport внутри собственного
процесса. Он не посылает команды реальному PX4. Проверки не доказывают
устойчивость VINS, физическое движение, взлёт, возврат и посадку.
